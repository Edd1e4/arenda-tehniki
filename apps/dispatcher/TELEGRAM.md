# Telegram: личный тест

## Статус
Подготовлен адаптер Telegram к локальному диспетчеру. Реальное подключение проверяется после запуска пользователем; токен не проверялся запросом из среды разработки.

## Запуск одной командой
Из папки диспетчера выполнить `node start.mjs` или запустить start-all.cmd. Программа читает .env и .env.telegram рядом с собой, поднимает диспетчер на 127.0.0.1:4388 и только после готовности порта запускает Telegram. Достаточно одного открытого окна. Если порт занят прежним диспетчером, остановить его Ctrl+C и повторить запуск. При ошибке Telegram диспетчер остаётся доступен до Ctrl+C.

## Раздельный запуск (дополнительный вариант)
1. Диспетчер server.mjs должен работать на 127.0.0.1:4388.
2. Записать токен только в .env.telegram: TELEGRAM_BOT_TOKEN=...
3. В другом окне из папки диспетчера выполнить:
```sh
node --env-file=.env.telegram telegram.mjs
```
4. Программа напечатает имя бота и команду /start с одноразовым кодом. Отправить эту команду своему боту в личном чате в течение 10 минут.
5. После подключения бот принимает сообщения только из этого личного чата и от этого пользователя. Другие чаты игнорируются, их тексты не отправляются в Claude.
6. /new — новая заявка; /save или кнопка — сохранить готовый черновик в общий локальный журнал; /help — помощь.

## Ограничения
- Пока это личный тест, не публичный приём клиентов.
- Оба окна программ и компьютер должны работать для ответов бота.
- Telegram хранит сообщения по своим условиям; текст тестового диалога передаётся через локальный сервер в Claude и расходует API-баланс. Использовать учебные адреса и контакты.
- Состояние привязки и позиция чтения обновлений хранятся в data/telegram-state.json. Переписка — только в памяти процесса до /new, перезапуска или часа без активности.
- Черновик до сохранения теряется при перезапуске локального диспетчера. Сохранённые заявки остаются в журнале.
- Запись заказов выполняет только server.mjs: бот не пишет напрямую в orders.json, чтобы избежать конфликтов двух процессов.
- Токен .env.telegram, состояние и заявки исключены из Git. Код не печатает токен, ссылки Bot API с токеном, тексты переписки или контакты в консоль.
- Существующее подключение через webhook не сбрасывается автоматически. getUpdates несовместим с активным webhook.
- Голосовые сообщения, исходящие звонки, платежи, автоматическая цена и СМС не подключены.
- Повторное сохранение того же черновика не создаёт дубль. Доставка сообщений Telegram после аварийного завершения не гарантирует «ровно один раз».
- Не запускать несколько копий бота одновременно.

Документация: https://core.telegram.org/bots/api#getupdates и https://core.telegram.org/bots/api#sendmessage
