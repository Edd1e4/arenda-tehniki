# Основа диспетчера

Есть локальный текстовый тест с подключением Claude: см. CLAUDE-SETUP.md. Его запросы отправляются в Anthropic и оплачиваются по API.
Модуль intake.mjs сам ничего не отправляет и не сохраняет. Звонки, мессенджеры, база заказов и СМС не подключены.

## Проверка
Из корня репозитория, Node.js 22 или новее:
```sh
node --test apps/dispatcher/intake.test.mjs
```

## Подключение
Адаптер Claude извлекает поля из разговора и вызывает reviewIntake(input, { today }), передавая текущую московскую дату YYYY-MM-DD.
Поля: cargo, pickup, dropoff, date, time, dimensions, contact, weightKg, zone; точность адреса определяется обязательными pickupStreet/pickupHouse и dropoffStreet/dropoffHouse; длина, ширина, высота — положительные числа lengthCm/widthCm/heightCm в сантиметрах, число мест — положительное целое pieceCount; необязательные requestedVehicle и needsHuman.
zone заполняется только после проверки маршрута; модуль не геокодирует адреса.

needs_details — продолжить уточнение; human_review — нужен человек; ready_for_quote — данных достаточно для расчёта, но заказ не подтверждён.
Ни один статус не означает, что цена определена, автомобиль подходит по габаритам, заказ сохранён, передан или забронирован.
Нужно отдельно проверить габариты, маршрут и въезд, наличие, финальную цену, затем реализовать хранение и явное подтверждение.

Не хранить реальные заявки и контакты клиентов в публичном GitHub.
Модульные тесты проверяют правила, а не качество разговоров будущей модели. Перед запуском нужны отдельные тесты диалогов и интеграций.

Для одного города без улицы/дома, двух размеров вместо трёх и неизвестного количества мест обязательны уточнения. Полнота адреса — проверка заполненности, не геокодирование и не подтверждение существования адреса. Размеры кузовов всё ещё требуют проверки человеком. Если данные клиенту неизвестны, можно запросить человека.
Автономный demo.html — отдельный ранний учебный пример; живой адаптер использует актуальный intake.mjs.
